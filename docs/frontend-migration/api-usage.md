## Authentication requests

All requests below use [djangoAuth.request](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/frontend/js/lib/djangoAuth.js) with base `/api/rest-auth`. Backend mounting is through `rest_auth.urls` and `rest_auth.registration.urls`; registration and profile serializers are customized. Token storage/startup/return-navigation details are in [routes](routes.md).

| Method/path | Caller | Payload and effects |
| --- | --- | --- |
| GET `/api/rest-auth/user/` | `authenticationStatus`, global login callback and ProfileController | Cached startup auth promise; profile has username, privilege/resource/request information consumed by the UI. |
| POST `/api/rest-auth/login/` | LoginController and LoginModalController | `{username,password}`; stores returned `key` in localStorage, sets Authorization default, broadcasts login, refreshes profile and returns to destination/search. |
| POST `/api/rest-auth/logout/` | NavbarController | Empty body; only successful response clears local token/header and broadcasts logout. Global listener goes home. |
| POST `/api/rest-auth/registration/` | SignupController | `{username,password1,password2,email}`; password copied into both fields. Watchers also POST partial bodies with other fields null as username/email probes; do not mistake these for read-only endpoints. |
| POST `/api/rest-auth/registration/verify-email/` | SignupVerifyEmailKeyController | `{key}` from URL; invoked on entry, navigates to success or displays error. |
| POST `/api/rest-auth/password/reset/` | ResetPasswordController | `{email}`; requests email; helper returns response and controller expects `response.success`. Verify real response schema. |
| POST `/api/rest-auth/password/reset/confirm/` | ResetPasswordConfirmController | `{uid,token,new_password1,new_password2}`; both passwords sourced from one input; goes to nested success. |

The helper adds `status` to error data and synthesizes `non_field_errors` for network failures, whereas controllers commonly expect `general_errors` (the configured DRF non-field key). Signup error handling directly calls `.join()` on email and username errors without checking their presence. Exact response/failure states require browser tests.

## Orphaned, indirect and non-API requests

- `ToolVersionProvider.getVersions` declares GET `/api/tool/:toolId/version`; no caller and no matching backend URL were found. `ToolLatest.get` is a separate unresolved symbol in the unregistered `newVersionOf` branch.
- `djangoAuth.changePassword` declares POST `/api/rest-auth/password/change/` with `new_password1/new_password2`; `updateProfile` declares PATCH `/api/rest-auth/user/`. No current frontend callers found. Keep separate from supported UI workflows.
- `ToolListConnection.update`, `ToolCreateValidator.update` and unused default `$resource` actions are declared but not called on the traced paths. Do not infer backend support from a client factory method.
- Backend `/api/edit-permissions[/<pk>]`, `/api/f` or `/api/function`, workflow detail `/api/w/:id`, admin/allauth and sitemap routes exist without request callers in the current frontend source. Permissions editing here travels inside the resource payload. Public API compatibility still covers these independent consumers.
- Angular template requests, `/dist/*`, fonts, image assets and workflow image URLs are static/media dependencies. `index.html` loads Google Fonts, Google Analytics, Altmetric and Dimensions scripts; tool detail also dynamically injects Altmetric. Annotation and publication links open third-party sites. They are not registry CRUD calls, and their availability was not tested.
- Historical templates and bundled libraries may contain old endpoint examples. The inventory traces maintained `js`/`components` request code and active template chains, while [routes](routes.md) records unresolved legacy navigation. Checked-in generated bundles were not rebuilt or used as proof of current runtime behavior.

## Verification scope

Cross-checked `$http`, `$resource`, the authentication wrapper, dynamic JSON-LD requests, endpoint literals and frontend templates against backend URL declarations and handlers. No project-owned `fetch`, XMLHttpRequest or jQuery Ajax request path was found outside these callers. No requests were issued to a live server. Payload normalization, error contracts and all mutation authorization require the regression work listed in [risk register](risk-register.md).

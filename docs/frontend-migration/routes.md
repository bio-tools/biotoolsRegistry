## Authentication and deep-link behavior

[djangoAuth.js](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/frontend/js/lib/djangoAuth.js) explicitly initializes token mode: `/api/rest-auth`, `use_session=false`, token in `localStorage.token`, `Authorization: Token ...` installed on `$http`. Startup GETs `/user/`; successful login refreshes `User.current`. Failed initial auth clears token/profile; successful logout clears them and navigates home. The helper also attempts an `X-CSRFToken` header via `$cookies['csrftoken']`; this does not prove session/CSRF behavior works. [Backend settings](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/backend/elixirapp/settings.py) enable session/CSRF middleware but DRF's configured default authentication is TokenAuthentication; session/basic/JWT classes are commented out. Deployment overrides remain uninspected.

[app.js](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/frontend/js/app.js) records intended state/parameters and tries to pause navigation for authentication before enforcing `roles: ['User']`; state errors go to `404`. Do not rely on this as a security boundary. Account controllers actually use `toState`/`toStateParams` for return navigation, while the guard also stores `returnToState` variables. Failed/slow startup auth and direct protected URLs need regression coverage. The `subdomain` state lacks `data.roles` entirely.

Activation links originate in [adapters.py](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/backend/elixir/adapters.py); password-reset HTML links in [password_reset_email.html](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/backend/templates/registration/password_reset_email.html). Preserve link shapes, token consumption, invalid/expired states and return behavior during auth migration.

## Navigation cross-check and remaining surfaces

- Cross-checked all 40 state declarations, router templates, active `ui-sref` links and controller transitions against navbar, footer, home/community, detail controls, profile, requests and domain templates. One state is abstract; `subdomain` is an incomplete overlapping declaration, not a proven second search implementation.
- Navbar reaches search/domains/communities/about, register, manager, profile and requests; Login and Sign-up both open the login modal. Footer additionally reaches stats. Detail/card/grid links use primary `tool` IDs; domain links use `/t?domain=...`; resource relations use `/<biotoolsID>`.
- [elxToolModule.html](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/frontend/partials/directives/elxToolModule.html) and [tool.affiliation.name.version.html](https://github.com/veitveit/biotoolsRegistry/blob/a1fc8b94067f33bc9047efc9c75ebe1579365a07/frontend/partials/tool.affiliation.name.version.html) contain active references to undeclared `edit.affiliation.name.version`; old/commented templates also mention `tool.affiliation.name.version`. No current route-to-template chain was found for these historical interfaces. Likewise `partials/documentation.html`, `help.html`, `register_tool.html`, `old_toolPage.html` and older signup activation partials are not declared routes. Do not invent a supported route from a filename.
- `ToolVersionProvider` requests a version endpoint absent from backend URLs; `ToolLatest` in the create controller's `newVersionOf` branch is not defined/injected, and `newVersionOf` is not a register URL parameter. Detail/grid code also passes undeclared `version` parameters. Treat these as unverified historical behavior.
- `/api/admin/`, `/api/accounts/`, `/api/rest-auth/`, `/api/sitemap.xml` and Django media handling are server surfaces outside the Angular router. Under the checked-in Apache mount, static paths are served separately. Preserve API/admin/account and asset routing during cutover; a frontend route is not an API alias merely because its path looks similar.
- No production request logs, reverse proxy outside this tree, browser baseline, email delivery or deployed bundle were checked. These uncertainties are tracked in [risk register](risk-register.md), and do not prevent completing this source inventory.

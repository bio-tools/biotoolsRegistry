# Workflow drafts and sharing

Signed-in users can save, list, open, rename and delete their own designs from `/workflows/design/`. Saving is an explicit action; the current browser draft and its JSON download remain available if a request fails. Updates and deletion use the last observed revision. A stale write is rejected rather than overwriting another tab's changes. Create requests use a client-generated identifier so retrying the same request does not create another draft. Session recovery verifies that the account has not changed and refreshes CSRF credentials without discarding the current design.

Sharing is optional. Creating a link replaces any earlier link; anyone holding it can view that saved design without signing in and can copy it into their own account. The link is read-only and has no expiry, but stops working when revoked, replaced, the draft is saved again, or the draft is deleted. Saving again revokes sharing so later edits are not accidentally disclosed. A random secret is stored only as a SHA-256 digest; the secret is in the link fragment and is sent to the server in a POST body rather than the request URL. The designer uses `Referrer-Policy: no-referrer`, and shared responses are not cached. People should treat the link as a secret: recipients can copy it and export its contents.

Every draft read and shared-link read checks current function visibility. Reads lock the draft and referenced resource/function rows while resolving the response, so a concurrent hide or revocation is ordered with the read; repeated references are resolved once per request. An owner reopening a draft with hidden, deleted or unresolvable functions receives placeholders and their own notes, without the hidden resource details. The unmodified original remains in the database; the interface offers saving the recovered design as a new draft and explicitly warns before replacing the original. Shared reads refuse to disclose a design with an unavailable function. Changed but still public functions remain as snapshots and require review before reconnecting. References, input/output identities, evidence, schema/vocabulary revisions and unknown compatible extension fields survive ordinary JSON round trips. Imports validate size, types, graph shape, connection endpoints, cycles and evidence before replacing the browser draft.

The `elixir.0007_workflow_design` migration creates a separate table and has been applied to the local preview. Back up saved designs before rolling this migration back: reversing it deletes that table and its drafts. Existing image workflows and their API are not modified. These designs are descriptions only; they are neither executable files nor uploaded analysis data.

Backend tests cover owner isolation, CSRF, account changes, simultaneous saves, idempotent retries, share/revoke, automatic revocation on save, hidden and deleted records, safe placeholders and invalid graph rejection. A coordinated concurrent test verifies that a shared read is ordered before a hide or revocation and that later reads are denied. The migration was reversed and a backup restored in the isolated test database on both Python runtimes; the preview database was not rolled back. Both local proxies passed browser tests for private saving, read-only viewing, copying, revocation and expired-session recovery with a disposable account. Broader large-dataset testing and an independent security review of sharing remain part of workflow acceptance and production readiness.
